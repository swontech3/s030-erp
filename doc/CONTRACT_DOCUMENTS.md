## A. ★ 전대차 비상주 특례 — 두 문서의 금액이 갈리는 자리

```
호실 1~2건이고 그 전부가 비상주(ROOM_TP = VR)  → 기준가(standard_fee)
그 외 (3건 이상 · 비상주 아닌 줄이 섞임)        → 실계약가(monthly_fee)
```

전대차계약서는 세무서 제출용이다. 비상주는 할인폭이 커서 실제 계약금액으로 내면
세무서가 인정하지 않는 경우가 많다.

**화면은 이 분기를 다시 쓰지 않는다.** `calcSubleaseMonthlyPayment()` 하나를 부르고 끝이다.
판정 조건이 두 벌이 되면 문서에 찍힌 숫자와 「어느 기준인가」가 어긋날 수 있다.

> 조건에 이름을 붙여 `usesSubleaseStandardFee()` 로 **내보내기는 했다.** 다만 용도는
> 시험과 검증 보고뿐이고, `calcSubleaseMonthlyPayment` 가 같은 함수를 쓴다 —
> 조건이 한 곳이라는 것은 그대로다. 금액을 이걸로 갈라 만들면 안 된다.

### 실제로 눌러서 확인한 숫자 (계약 3건, 2026-09-20)

| 계약 | 구성 | 이용계약서 월납부액 | 전대차 월회비 | |
|---|---|---|---|---|
| **A** | 비상주 1건 (기준 50,000 / 계약 30,000) | **33,000 원** | **55,000 원** | ★ 다르다 — 특례 |
| **B** | 비상주 3건 (같은 조건 ×3) | 99,000 원 | 99,000 원 | 같다 — 3건이라 특례 아님 |
| **C** | 비상주 1건 + 지정석 1건 | 308,000 원 | 308,000 원 | 같다 — 섞여서 특례 아님 |

A 의 두 숫자가 다른 것이 이 작업의 핵심이다. 33,000 = 30,000 + 부가세 3,000(실계약가),
55,000 = 50,000 + 부가세 5,000(기준가). **부가세도 고른 기준액에서 다시 계산한다** —
기준가로 가면서 실계약가의 부가세를 얹으면 금액과 세액의 근거가 달라진다.

계약 3건은 확인 후 **지웠다**(`tb_s080_contracts` 9행·`contract_spaces` 18행·`status_history` 18행).

## B. ★ 주소 — 자리마다 출처가 다르다

시안의 `data-blankable` 이름이 근거다. 전대차 서명란 을 블록은 다섯 칸이 모두
`c*`(= Company) 로 묶여 있다 — `cCeoBlank` · `cCorpnoBlank` · `cBiznoBlank` ·
**`cAddressBlank`** · `cPhoneBlank`. 즉 그 주소는 **회사 레코드에서 온다.**

| 자리 | 출처 | 근거 |
|---|---|---|
| 이용계약서 「주소」(섹션1 4행) | 회사 주소 (우편번호+기본+상세) | 명세 「우편번호 + 기본 + 상세」 |
| 이용계약서 서명란 「을 :」 | 같은 값 | 시안이 같은 문자열 |
| 전대차 서명란 을 「주소」 | 같은 값 (**우편번호 없이**) | 시안 `cAddressBlank` |
| **전대차 2조 2항 「대상」** | **건물 주소 + 계약호실** | 시안이 `301호`(회사)와 `1-10호`(계약호실)를 **다르게** 찍는다 |

마지막 줄만 사업장 주소다. 국세청에 신고한 주소와 같아야 하기 때문이고,
`CONTRACT_PREMISES.PREFIX + {contract_room}호 + SUFFIX` 로 만든다.
**계약호실이 없으면 그 자리를 비운다** — 아무 호실이나 넣지 않는다.

### ⚠️ 「회사 주소」가 무엇인지 — 지금은 **대표자 주소 하나뿐**이다

`tb_s080_companies` 에는 주소가 **세 벌** 있다:

| 컬럼 | 뜻 | 상태 |
|---|---|---|
| `zip_code` · `address` · `address_detail` | 사업장 | **API 가 내려주지 않고 입력란도 없다. 값 NULL** |
| `head_zip_code` · `head_address` · `head_address_detail` | 본점 | 같음 |
| `ceo_zip_code` · `ceo_address` · `ceo_address_detail` | 대표자 | **계약 폼 섹션 1 이 입력·저장한다** |

계약서는 `ceo_*` 를 쓴다. 근거는 그 입력칸 자신이다 —
`SectionCompany.tsx` 의 힌트가 **「계약서에 인쇄되는 대표자 주소입니다」** 이고,
`GET /companies/:id` 가 내려주는 주소도 이것뿐이다.

> **남은 문제.** 「대표자 자택 주소」와 「사업자등록증상 주소」가 다른 회사라면 계약서에
> 자택이 인쇄된다. 지금 데이터로는 구분할 방법이 없다(사업장 칸이 비어 있고 채울 화면도 없다).
> **사업장 주소 입력란을 섹션 1 에 만들 것인지 판단이 필요하다.** 만들기 전까지는
> 이 문서가 쓰는 주소가 무엇인지 운영자가 알고 있어야 한다.

## C. ★ 채우지 못해 비워 둔 값

**계약서에 지어낸 값이 인쇄되는 것이 가장 나쁘다.** 그래서 없는 값은 비우고,
그 자리에 기입선(밑줄)을 그린다 — 명세의 「값이 비어 있을 때만 기입선을 표시」 그대로다.
「미상」·「-」·「해당없음」 같은 글자는 쓰지 않는다. 그건 사람이 적은 값처럼 보인다.

| 값 | 어떻게 했나 |
|---|---|
| **확정·취소 일자** | 애초에 이 문서에 자리가 없다. 서명 날짜는 `Contract.contractDate`(계약일자)를 쓴다 — 명세의 `signDate` 가 그것이다 |
| 계약일자가 비면 | 「____ 년 __ 월 __ 일」(이용계약서) / 「20__ 년 __ 월 __ 일」(전대차) — 명세가 두 문서에 **다른 문자열**을 쓴다 |
| 5조 납부일 | 계약일자의 **일(day)** 만. 계약일자가 없으면 기입선 |
| 계약호실 | 없으면 2조 2항의 호실 자리만 기입선 |
| 법인등록번호 | 개인·개인사업자는 없다 → 기입선 (검증에서 실제로 비어 나왔다) |
| 첫달납부액 | 납부방법을 못 고르면 **계산되지 않는다.** 0 원으로 찍지 않고 기입선 — 0 원은 「공짜」라는 값이다 |
| **센터명 · 담당자** | `CONTRACT_DEFAULTS.DEFAULT_CENTER` / `DEFAULT_MANAGER`(CONT-14). 지점 설정 화면도 API 도 아직 없다. 건물 행의 `center_manager` 는 `E202600001` 같은 **사번**이라 이름을 못 얻는다 |
| 오피스 정보 전화·팩스·이메일·은행 | 명세에 값이 적혀 있어 그대로 상수(`CONTRACT_OFFICE`). 건물 행의 `bank_name`·`bank_account` 는 빈 문자열이다 |
| 갑(임대인) 고정값 | 명세 「임대인 고정값」 그대로 상수(`CONTRACT_LESSOR`). 운영사 행(`tb_s080_tenant010`)에 법인등록번호·사업자번호 칸이 비어 있다 |

## D. ★ 금액 계산을 다시 짜지 않았다

전부 `@swonbiz/shared` 다 — `calcTotals` · `calcFirstPayment` · `calcSubleaseMonthlyPayment` ·
`calcEndDate`. 화면 코드에 `Math.round` 도 `setMonth` 도 없다.

```
$ grep -rn "Math\.round|setMonth|getMonth()" packages/web/src
```

남는 것은 날짜 포매팅(`getMonth()`)과 파일 크기 표시(`Math.round`)뿐이고 금액이 아니다.
`form-model.ts` 머리말이 같은 규칙을 적고 있다 — *「이 파일에 Math.round 도 setMonth 도 없다.
있으면 그 순간 두 벌이 된다.」*

## E. 인쇄 — 잡은 결함 둘

### E-1. ★★ 절대위치가 **뒷장을 통째로 삼켰다**

처음에는 인쇄 CSS 를 «전부 감추고 문서만 절대위치로 좌상단에 끌어낸다»로 만들었다.
화면에서 멀쩡했고 PDF 도 나왔다. **그런데 전대차계약서가 3장 분량인데 2장만 인쇄됐다.**

절대위치 요소는 정상 흐름에서 빠진다. 흐름에서 빠지면 브라우저가 페이지를 나눌 높이를
잃고 조상(모달)의 높이만큼만 찍고 멈춘다. 10조까지 있는 계약서의 뒷부분이 **오류 없이
조용히** 사라진다 — 인쇄해 보기 전에는 모른다.

**고친 방식**

1. 모달을 **`document.body` 로 포털**한다(`createPortal`). 문서가 body 바로 밑 정상 흐름에 놓인다
2. 인쇄할 때 **body 의 다른 자식만** `display:none` 한다
3. 모달 껍데기는 **크기 제한만** 푼다(`height:92vh` · `overflow` · `padding`). 위치는 건드리지 않는다

**검사도 바꿨다.** 「PDF 가 나온다」만 보면 뒷장이 잘려도 통과한다. 지금은
**필요한 장수(문서 높이 ÷ A4 인쇄 높이)와 실제 PDF 장수를 맞춰 본다.**

```
이용계약서   내용 1.31장 → PDF 2장 ✔
전대차계약서 내용 2.71장 → PDF 3장 ✔   (고치기 전: 2장 — 잘렸다)
```

### E-2. 종료일이 빈 채로 인쇄됐다

이용기간이 「2026.01.15 ~ **(6개월)**」로 나왔다 — 종료일이 없다.
`endDateOf()` 는 **화면 표기**라 점을 찍은 `2026.07.14` 를 주는데, 문서의
`periodLabel()` 은 ISO(`YYYY-MM-DD`)만 날짜로 인정한다. 형식이 안 맞으니 조용히 비웠다.

`endDateIsoOf()` 를 만들어 ISO 를 주고, `endDateOf` 가 그 결과를 점으로 바꿔 쓰게 했다 —
**계산은 여전히 한 곳**이고 형식만 둘이다.
