## 0. 먼저 네 줄

```
① 삐용 주소를 코드에 박지 않는다. packages/api/.env 에서 읽는다
② 계통(개발계/가동계)도 추측하지 않는다. BBIYONG_SYSTEM 이 선언한다 — 주소와 한 쌍이다
③ 가동계는 HTTPS 로만 주고받는다(삐용 회신 ①). http 면 **기동하지 않는다**
④ 지금 서 있는 곳은 개발계다. 가동계로 가려면 §2 의 표를 위에서 아래로 훑는다
```

| 계통 | `BBIYONG_SYSTEM` | `BBIYONG_BASE_URL` (API) | `NEXT_PUBLIC_BBIYONG_WEB_URL` (화면) | 무엇 |
|---|---|---|---|---|
| **개발계** | `dev` | `http://192.168.0.22:8082` | `http://192.168.0.22:3000` | 삐용을 개발 중인 PC. **지금 여기다** |
| **가동계** | `prod` | `https://192.168.0.14:8082` | **아직 못 받았다**(§4 M3) | ERP 완성 후 운영할 서버 |

> ★★ **삐용은 화면과 API 가 다른 서버다.** 포트가 `3000`(화면)·`8082`(API)로 갈린다.
> 화면 주소는 **web 쪽 변수**(`packages/web/.env`)이고 API 주소는 **api 쪽 변수**다 —
> 두 파일이다. 비밀번호 초기화는 **화면에서만** 되므로(ERP 에 보내는 API 가 없다 —
> 회신 2026-10-05) 로그인 화면이 그 주소를 쓴다.

> ⚠️ **삐용이 준 가동계 주소는 `http://192.168.0.14:8082` 로 HTTPS 가 아니다.**
> 그래서 **지금은 가동계로 뜰 수 없다** — `env.ts` 가 기동을 막는다(의도한 것이다).
> 삐용 쪽 HTTPS 가 켜지면 위 표의 주소를 확정한다. 그때 `BBIYONG_SYSTEM` 은 그대로 `prod` 다.

## 1. 왜 포트로 가르지 않는가

2026-09-30 까지 ERP 는 **포트**로 계통을 갈랐다 — `8082=개발계` · `8080=가동계`.
그 규칙이 깨졌다: 개발계 `.22:8082` · 가동계 `.14:8082` 로 **포트가 같다.**

호스트로 갈라도 같은 사고가 반복된다 — 가동계가 도메인·HTTPS 로 바뀌는 순간 또 틀린다.
그래서 **추측을 그만두고 사람이 선언한다.** 주소를 코드에 박지 않는 것과 같은 이유다.

★ 대가: **주소만 바꾸고 계통을 안 바꾸면 코드가 잡아낼 방법이 없다.**
그래서 기동 로그 맨 위에 **주소와 계통을 함께** 찍는다. 둘이 어긋나 보이면 그 자리에서 멈춘다.

```
개발계   [BBIYONG] http://192.168.0.22:8082  (개발계)
MOCK     [BBIYONG] MOCK — … · 실연동 시 붙을 곳: http://192.168.0.22:8082  (개발계)
가동계   ======================================================================
         ★★  [BBIYONG] https://192.168.0.14:8082  — 가동계(운영) ★★
         …
```

기동 로그를 놓쳤으면 `GET /health` 의 `bbiyong.system` 이 같은 값을 답한다.

## 3. 토큰이 만료됐을 때 (2026-09-30 변경)

ERP 세션은 **7일**이고 삐용 토큰은 그보다 짧다. **세션 기간은 그대로 둔다** — 운영자를
매일 로그인시키지 않는다. 대신 삐용을 부르기 직전에 토큰을 살린다.

```
삐용 호출 직전   토큰의 exp 를 읽는다 → 죽었으면 재발급(auth/re-issue) 먼저
삐용이 401       재발급 한 번 → 새 토큰으로 다시 부른다
재발급도 실패     ERP 세션 폐기(revoked_at) → 401 session_expired
                 → 「세션이 만료되었습니다. 다시 로그인해 주세요」 + 쿠키 삭제 → /login
삐용 장애(연결)   503 「인증 서버에 연결할 수 없습니다」 — **세션을 죽이지 않는다**
```

★ **만료 시간(30분·24시간·7일)은 ERP 코드에 없다.** 개발계·가동계가 각 DB 의
`code010` 으로 분리돼 값이 다를 수 있다(회신 ⑤) — 그래서 토큰 안의 `exp` 만 읽는다.
**계통에 따라 다르게 도는 코드가 없다**는 뜻이기도 하다: 개발계에서 시험한 경로가
가동계에서도 같은 경로다.

★ 삐용을 부르는 자리는 `session/bbiyongToken.ts` 의 `callBbiyong` **하나다.**
이걸 거치지 않고 세션에서 토큰을 직접 꺼내 쓰면 그 경로만 재발급을 빠뜨린다.
