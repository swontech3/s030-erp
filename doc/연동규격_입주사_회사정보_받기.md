# 연동 규격 — 삐용 → ERP : 입주사 회사 정보 받기

**작성:** 2026-10-23 · **대상:** 삐용 팀 · **근거:** 결정 2026-10-23 · 삐용 회신 2026-10-23(번호는 숫자만)
**짝:** ERP → 삐용 「보내기」는 기존 `erp-patch-org` 를 그대로 쓴다(회사명 · 사업자번호 · 법인번호 · 업태 · 종목, 번호는 숫자만, 주소는 보내지 않음).

삐용에서 ERP 입주사의 회사 정보를 고치면 이 주소를 불러 주세요. ERP 입주사 정보에 반영합니다.

## 1. 주소

```
POST <ERP API 주소>/companies/bbiyong/org-changed
Authorization: Bearer <운영사 회원의 삐용 accessToken>
Content-Type: application/json
```
- ERP API 주소(개발계 · 가동계)는 따로 알려 드립니다.
- 서버끼리 쓰는 키는 만들지 않습니다(연동규격 Q1). 토큰은 **삐용이 발급한 운영사 회원의 accessToken** 입니다.

## 2. 부르는 쪽 확인

ERP 는 실어 온 토큰 그대로 삐용 `GET /rest/v1/s021000000/my-menus` 를 부릅니다(2026-10-25 넓힘).
목록에 **단체관리 `S021100010`** 이 있으면 운영사로 받습니다. 없으면 `GET /rest/v1/s021200010/my-orgs` 의
지금 계정(`current: true`) 줄의 `orgId` 가 **본문 `orgId`** 와 같을 때만 받습니다.
my-menus 의 `data` 는 객체 목록 `{ menuCode, keys }` 와 옛 화면코드 문자열 목록을 둘 다 읽습니다.

| 경우 | ERP 응답 |
|---|---|
| 목록에 `S021100010` 있음(운영사) | 받음 |
| `S021100010` 없음 · my-orgs 지금 계정의 `orgId` = 본문 `orgId`(자기 회사) | 받음 |
| `S021100010` 없음 · 지금 계정의 `orgId` ≠ 본문 `orgId`(남의 회사) · 본문 `orgId` 를 읽을 수 없음 | **HTTP 403** |
| 토큰이 없음 · my-menus 또는 my-orgs 가 거절(401 · 403 · 본문 실패 · 지금 계정 줄 없음) | **HTTP 403** |
| ERP 가 삐용 my-menus · my-orgs 에 붙지 못함 | **HTTP 503** — 잠시 뒤 다시 보내 주세요 |

## 3. 본문

```json
{ "orgId": 324, "orgCode": "Z04",
  "orgName": "한성무역", "bizNumber": "1058768687", "corpNumber": "1110002313123",
  "businessType": "도매", "businessItem": "무역" }
```

| 칸 | 필수 | 규칙 |
|---|---|---|
| `orgId` | ✅ | 삐용 단체 ID(양의 정수). **이 값으로 입주사를 찾습니다** |
| `orgCode` | | 받기는 하지만 보지 않습니다 |
| `orgName` | | 회사명 |
| `bizNumber` | | 사업자번호 · **숫자 10자리**(하이픈 없이) |
| `corpNumber` | | 법인번호 · **숫자 13자리**(하이픈 없이) |
| `businessType` | | 업태 |
| `businessItem` | | 종목 |

- **받은 칸만 바꿉니다.** 칸이 없거나 `null` · 빈 문자열(`""`)이면 **안 바꿉니다**. 빈 값으로 지우는 일은 없습니다.
- **주소(`zipCode` · `address` · `detailAddress`)는 받지 않습니다.** 보내도 보지 않습니다. 위 칸 밖도 보지 않습니다.
- 번호는 ERP 가 하이픈 넣은 모양(`105-87-68687` · `111000-2313123`)으로 바꿔 저장합니다.
- 받은 값을 삐용에 다시 보내지 않습니다. 같은 수정이 되돌아가지 않습니다.

## 4. 응답

성공은 모두 **HTTP 200** 입니다. 실제로 썼는지는 `applied` · `skipped` 로 알 수 있습니다.

```json
{ "ok": true, "applied": true,  "skipped": null }
{ "ok": true, "applied": false, "skipped": "not_found" }
```

| `skipped` | 뜻 |
|---|---|
| `null` | 반영했습니다 |
| `not_found` | 그 단체 ID 에 연결된 ERP 입주사가 없습니다. 아무것도 하지 않았습니다(장애가 아닙니다) |
| `no_fields` | 바꿀 칸이 없었습니다(전부 빈 값) |

실패 응답:

| HTTP | 본문 | 다시 보내면 |
|---|---|---|
| 400 | `{ "error": "invalid_request", "message": "...", "errors": [{ "field": "bizNumber", "message": "..." }] }` — 칸 하나라도 틀리면 **아무 칸도 쓰지 않습니다** | 값을 고쳐야 합니다 |
| 403 | `{ "error": "forbidden", "message": "삐용 단체관리 권한이 있는 토큰이 아닙니다" }` | 토큰 · 역할을 바꿔야 합니다 |
| 409 | `{ "error": "duplicate", "message": "다른 입주사가 쓰는 사업자번호입니다" }` — **아무 칸도 쓰지 않습니다** | 값을 고쳐야 합니다 |
| 503 | `{ "error": "bbiyong_unavailable", "message": "..." }` | 잠시 뒤 다시 보내면 됩니다 |
