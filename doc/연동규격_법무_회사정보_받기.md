# 연동 규격 — 삐용 → 법무 : 회사 정보 받기

**작성:** 2026-10-23 · **대상:** 삐용 팀 · **근거:** 삐용 회신 2026-10-23(번호는 숫자만 · 단체코드와 단체 ID 를 함께 보냄)
**짝:** 법무 → 삐용 「보내기」는 기존 `erp-patch-org` 를 그대로 쓴다(번호는 숫자만 보낸다).

삐용에서 회사 정보를 고치면 이 주소를 불러 주세요. 법무 서비스(비입주사)의 회사 정보에 반영합니다.

## 1. 주소

```
POST <ERP API 주소>/legal/bbiyong/org-changed
Authorization: Bearer <운영사 회원의 삐용 accessToken>
Content-Type: application/json
```
- ERP API 주소(개발계 · 가동계)는 따로 알려 드립니다.
- 서버끼리 쓰는 키는 만들지 않습니다(연동규격 Q1). 토큰은 **삐용이 발급한 운영사 또는 그 회사 회원의 accessToken** 입니다.

## 2. 부르는 쪽 확인

ERP 는 실어 온 토큰 그대로 삐용 `GET /rest/v1/s021000000/my-menus` 를 부릅니다(2026-10-25 넓힘).
목록에 **단체관리 `S021100010`** 이 있으면 운영사로 받습니다. 없으면 `GET /rest/v1/s021200010/my-orgs` 의
지금 계정(`current: true`) 줄의 `orgId` 가 **본문 `orgId`** 와 같고, my-menus 에 **단체 수정 키**(ERP 공통 코드
`BBIYONG_EDIT_GRANT` 의 `ORG_SELF` — `화면코드:키`, 지금 `S021100021:F002`)가 있을 때만 받습니다(삐용 통합 시험 C3, 2026-10-25).
my-menus 의 `data` 는 객체 목록 `{ menuCode, keys }` 와 옛 화면코드 문자열 목록을 둘 다 읽습니다.

| 경우 | ERP 응답 |
|---|---|
| 목록에 `S021100010` 있음(운영사) | 받음 |
| `S021100010` 없음 · my-orgs 지금 계정의 `orgId` = 본문 `orgId`(자기 회사) · 단체 수정 키 있음 | 받음 |
| `S021100010` 없음 · 지금 계정의 `orgId` ≠ 본문 `orgId`(남의 회사) · 본문 `orgId` 를 읽을 수 없음 · 단체 수정 키 없음 | **HTTP 403** |
| 토큰이 없음 · my-menus 또는 my-orgs 가 거절(401 · 403 · 본문 실패 · 지금 계정 줄 없음) | **HTTP 403** |
| ERP 가 삐용 my-menus · my-orgs 에 붙지 못함 | **HTTP 503** — 잠시 뒤 다시 보내 주세요 |

## 3. 본문

```json
{ "orgId": 9003, "orgCode": "Z99",
  "zipCode": "06097", "address": "서울 강남구 테헤란로 1", "detailAddress": "3층",
  "bizNumber": "1058768687", "corpNumber": "1110002313123" }
```

| 칸 | 필수 | 규칙 |
|---|---|---|
| `orgId` | ✅ | 삐용 단체 ID(양의 정수). **이 값으로 회사를 찾습니다** |
| `orgCode` | | 받기는 하지만 비교하지 않습니다 |
| `zipCode` | | 본점 우편번호 · 10자 이내 |
| `address` | | 본점 주소 |
| `detailAddress` | | 본점 상세주소 · 200자 이내 |
| `bizNumber` | | 사업자번호 · **숫자 10자리**(하이픈 없이) |
| `corpNumber` | | 법인번호 · **숫자 13자리**(하이픈 없이) |

- **받은 칸만 바꿉니다.** 칸이 없거나 `null` · 빈 문자열(`""`)이면 **안 바꿉니다**. 빈 값으로 지우는 일은 없습니다.
- 위 일곱 칸 밖(회사명 · 업태 · 종목 등)은 보내도 보지 않습니다.
- 번호는 ERP 가 하이픈 넣은 모양(`105-87-68687` · `111000-2313123`)으로 바꿔 저장합니다.
- 받은 값을 삐용에 다시 보내지 않습니다. 같은 수정이 되돌아가지 않습니다.

## 4. 응답

성공은 모두 **HTTP 200** 입니다. 실제로 썼는지는 `applied` · `skipped` 로 알 수 있습니다.

```json
{ "ok": true, "applied": true,  "skipped": null }
{ "ok": true, "applied": false, "skipped": "not_found" }
```

| `skipped` | 뜻 |
|---|---|
| `null` | 반영했습니다 |
| `not_found` | 법무 회사 정보가 없는 단체입니다. 아무것도 하지 않았습니다(장애가 아닙니다) |
| `tenant` | 입주사 단체입니다. 쓰지 않았습니다 — 입주사 정보는 ERP 회사 표가 정본입니다 |
| `no_fields` | 바꿀 칸이 없었습니다(전부 빈 값) |

실패 응답:

| HTTP | 본문 | 다시 보내면 |
|---|---|---|
| 400 | `{ "error": "invalid_request", "message": "...", "errors": [{ "field": "bizNumber", "message": "..." }] }` — 칸 하나라도 틀리면 **아무 칸도 쓰지 않습니다** | 값을 고쳐야 합니다 |
| 403 | `{ "error": "forbidden", "message": "운영사이거나 그 회사의 토큰이 아닙니다" }` | 토큰 · 역할을 바꿔야 합니다 |
| 503 | `{ "error": "bbiyong_unavailable", "message": "..." }` | 잠시 뒤 다시 보내면 됩니다 |
