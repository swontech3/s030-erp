## 보내는 것

### ① 확정된 ERP 접속 주소 — CORS 허용 목록 등록용

| 환경 | 주소 | 용도 |
|---|---|---|
| 운영 (제안) | `https://erp.swonbiz.com` | 브라우저 오리진. **CORS 허용 목록에 이 오리진을 등록**해 주십시오 |
| 개발 | `http://localhost:3000` | 개발 PC 브라우저 오리진 |

보충 설명 두 가지입니다.

- **브라우저가 삐용 API를 직접 부르지 않습니다.** ERP 서버(Fastify)가 서버끼리 삐용 API를 호출하고, 브라우저에는 ERP가 만든 불투명한 세션 쿠키(`erp_sid`) 하나만 내려갑니다. 삐용 access·refresh 토큰은 ERP 서버에만 암호화 보관됩니다(지시서 1-4). 그래서 실제로는 **ERP 서버의 송신 IP**를 허용해 주시는 것이 더 중요할 수 있습니다 — 서버 IP는 배포 시점에 별도로 드리겠습니다.
- 그럼에도 오리진 등록을 요청드리는 것은, 삐용 비밀번호 재설정 화면으로 나가는 외부 링크(로그인 화면의 "비밀번호 찾기")처럼 **브라우저가 삐용 화면으로 직접 이동하는 경로**가 있기 때문입니다.

### ② 화면 목록 — 페이즈 1분 (팝업·모달 포함)

지시서 2-6 ③의 형식에 맞춰 **화면코드 · 화면명 · 대상 · 동작**을 드립니다. 마스터 등록 시 코드는 **대문자**로 올려 주십시오(체계는 ③ 참조).

| 화면코드 (마스터 등록용) | ERP 내부 코드 | 화면명 | 모듈 | 대상 | 동작 | 비고 |
|---|---|---|---|---|---|---|
| `S0300000010` | `s0300000010` | 로그인 | 공통 | 전체 | VIEW | 인증 전 화면. 권한 판정 대상 아님 — 목록 완결성을 위해 기재 |
| `S0300000050` | `s0300000050` | ERP 셸 (사이드바·헤더) | 공통 | 운영사 · 입주사 | VIEW | 라우트 없는 레이아웃. **접근 가능 화면 목록에 이 코드가 포함돼야 셸이 뜹니다** |
| `S0300000080` | `s0300000080` | 접근 권한 없음 | 공통 | 전체 | VIEW | 로그인은 됐으나 접근 가능 화면이 0건일 때. 권한 판정 대상 아님 |

이번 페이즈에는 **팝업·모달이 없습니다** (`s0300000010p1` 조직 선택은 회신 ⑩ 전까지 보류).

자리만 있고 내용이 없는 화면 2개는 **다음 페이즈에서 제출**합니다: `s0300000060` 대시보드(운영사) · `s0300600010` 회의실 예약 현황. 다만 ERP는 홈 분기를 이 두 코드의 **권한 유무**로 정하므로(대시보드 권한 있음 → `/dashboard`, 예약 권한 있음 → `/booking`, 둘 다 없음 → 안내 화면), 마스터에 미리 등록해 두시면 홈 분기를 실 권한으로 시험할 수 있습니다.

### ③ 화면코드 체계 — ERP 현행 유지로 회신

지시서 2-7의 제안(`S03` + 업무그룹 3 + 순번 4 = 10자)에 대한 회신입니다. **ERP 현행 체계(`s030` + 업무구분 3 + 순번 4 = 11자, 팝업은 접미사 `p{n}`)를 유지**하겠습니다.

| | 삐용 제안 | ERP 현행 (채택) |
|---|---|---|
| 형식 | `S031000010` (10자) | `s0300200040` (11자) |
| 팝업 | 순번 뒤 2자리 | 접미사 `p1` → `s0300200040p1` (13자) |
| 대소문자 | 대문자 | 소문자 사용, **마스터 제출 시 대문자로 변환** (`toUpperCase()` 뿐이라 매핑표 불필요) |

이유는 하나입니다. 삐용 제안의 업무그룹은 **기능 단위**(100 입주계약·200 예약…)이고 ERP 업무구분은 **화면 조직 단위**(010 기준설정·020 입주사관리…)라, 변환하면 기준설정과 입주사관리가 둘 다 OFFICE(100)에 떨어져 **`S031000010`이 두 화면에 동시에 배정되는 충돌**이 납니다. 결정론적 변환이 불가능해 현행을 유지합니다. 지시서 2-7 자신이 "코드는 판단 근거가 아니다"라고 못박았으므로, 판정에는 영향이 없습니다.

**확인 요청:** 화면코드 컬럼이 **11자(팝업 13자)**를 받는지 확인 부탁드립니다(③에 딸린 항목).

## 받아야 하는 것 — ④⑤⑥⑦

아래 넷은 **삐용의 로그인 성공 처리 코드 한 곳**에서 전부 나옵니다. 그 함수(또는 컨트롤러)의 소스 한 파일을 공유해 주시면 네 항목이 한 번에 해소됩니다 — 따로따로 문서로 적어 주시는 것보다 정확하고 빠릅니다.

| # | 항목 | ERP가 지금 가정하고 있는 값 | 틀리면 어디가 바뀌는가 |
|---|---|---|---|
| ④ | 토큰 저장 위치 (클라이언트 관점) | ERP는 브라우저에 두지 않고 서버에 암호화 보관 | 지시서 1-2·1-4 정합 여부 확인용. ERP 쪽 변경 없음 |
| ⑤ | TTL · 갱신 방식 | refresh **7일** (폴백 가정). 갱신은 `/rest/v1/auth/re-issue` GET, access·refresh 둘 다 필요 | `packages/api/src/env.ts` 의 `sessionTtlMs` 상수 1개 |
| ⑥ | 토큰 내용 (클레임) | JWT 에 `memberId` 는 있고 **`orgId` 는 없다** (로그인 응답 본문에만) — 이 가정 위에 서버 세션 구조가 서 있습니다 | 맞으면 변경 없음. `orgId` 가 JWT 에 있어도 ERP는 응답 본문 값을 씁니다 |
| ⑦ | 로그인 API 요청/응답 규격 | `POST /rest/v1/s021200010/sign-in`, **HTTP 200 이어도 `body.status !== 200` 이면 실패** | `HttpBbiyongAuth` 구현체 1개 (Mock 과 교체) |

ERP 쪽에서 준비된 것: `BbiyongAuth`·`BbiyongAcl` 두 인터페이스 뒤에 Mock 구현이 있고, 페이즈 1~6 전부 Mock 으로 완주 가능합니다. **회신이 오면 어댑터 구현체 하나씩만 교체합니다** — 다른 코드는 손대지 않습니다.

### 함께 받고 싶은 것 (우선순위 순)

- **⑫ 권한 조회 API 규격** — 접근 가능 화면 **목록** 엔드포인트가 있는지가 핵심입니다(단건 check 만 있으면 사이드바를 그릴 수 없습니다). 응답에 화면코드·동작·범위(본인/회사) 3종이 들어가는지.
- **⑮ 공통 화면의 모듈 소속** — `tb_s020_module010`의 S03 모듈이 OFFICE·BOOKING·LEGAL·TAX·BILLING 5종뿐이라 셸·대시보드·설정을 붙일 자리가 없습니다. 없으면 홈 분기가 동작하지 않습니다.
- ⑩ 겸직 지원 여부 (`member010.org_id` 단일 컬럼) — `s0300000010p1` 조직 선택 화면 존폐.
- ⑬ 삐용 조직 목록 API — 입주사 ↔ 삐용 조직 연결 UI 드롭다운용(없으면 수기 입력으로 진행).
- ⑧ BILLING `provider_only_yn` / ⑨ 050 공개 화면 마스터 등록 여부 / ⑪ 삐용 미사용 입주사 계정 경로 / ⑯ 마스터 시드 리드타임.

## 참고 — 페이즈 1에서 ERP가 확정한 것 (삐용 쪽 변경 요청 아님)

- 세션: 불투명 `erp_sid` 쿠키(HttpOnly · Secure · SameSite=Lax), DB에는 SHA-256 해시만. 삐용 토큰은 서버 AES-256-GCM.
- 권한: 1단계 shadow — ERP는 화면 접근을 **막지 않고 기록만** 합니다(`tb_s080_acl_shadow_log`). 마스터 등록·⑫ 회신 후 실제 차단으로 올립니다.
- 데이터 스코프(`company_id`)는 shadow 대상이 아니며 1단계부터 강제됩니다 — 삐용 조직 ↔ ERP 입주사 연결(`link_s020_org_id`)이 없는 세션은 **0건**을 봅니다.
