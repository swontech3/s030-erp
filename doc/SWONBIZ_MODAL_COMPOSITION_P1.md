# 1차 팝업 화면 조합 명세

템플릿으로 직접 만들지 않은 화면을 기존 템플릿·DS 컴포넌트 조합으로 구성하는 방법.
**새로 설계하지 말 것.** 아래에 명시된 출처에서 마크업과 스타일을 그대로 가져온다.

> 대상: 1차 개발 범위 팝업 5종
> 2차 화면(센터 관리·멤버 관리·신청 대기·승인 큐)의 조합 명세는 2차 착수 시 별도 작성

---

## 공통 규칙

**모달 셸**

- `components/ds/Dialog.tsx` 를 셸로 사용. 오버레이·닫기·포커스 트랩·Esc 처리는 Dialog가 담당
- 폭: 폼 모달 640px / 계약서 미리보기 1000px / 확인 모달 480px
- 최대 높이 `92vh`, 초과 시 본문만 스크롤. 헤더·푸터는 고정
- 헤더 72px: 제목 18px weight 700 + 우측 닫기 IconButton
- 푸터 80px: 우측 정렬 버튼, 취소(ghost) → 주 액션(primary) 순

**폼 내부**

- 섹션 래퍼·라벨·필드 간격은 `ErpContractForm.dc.html` 의 섹션 1 구조를 따른다
- 필드 행 간격 20px, 섹션 간격 32px
- 금액·사업자번호·연락처 마스크는 `lib/format.ts` 로 일원화 (계약 폼과 동일 로직)
- 필수 표시는 인디고 도트. 오류는 `--color-danger`, 필드 하단 메시지

**상태**

- `entry` / `submitting`(폼 잠금 + 버튼 스피너) / `error`(상단 요약 + 필드 앵커)
- 저장 성공 시 모달 닫기 + Toast. **Toast 아이콘·색은 인디고** (녹색 금지)

## s0300200030p2 · 계약 등록

**출처**: `ErpMasterDetail.dc.html` 의 계약 등록 모달 — 3모드가 이미 구현되어 있음

3모드를 그대로 유지한다.

| 모드 | 진입 | 초기값 |
|---|---|---|
| `new-tenant` | 헤더 "신규 입주사 등록" | 전부 빈 값 |
| `new-contract` | 우측 "신규 계약" | 입주사 고정, 계약 정보만 입력 |
| `renew` | 계약 행 "재계약" | 직전 계약 값 복사, 기간만 갱신 |

- **이 모달은 계약을 생성만 한다.** 계약 항목·사용자·첨부는 계약 폼에서 입력
- 생성 후 `draft` 상태로 `/contracts/{id}` 이동
- `renew` 모드에서 복사 대상: 계약 항목 전체, 계약 조건, 사용자 목록
  첨부는 복사하지 않는다 (서류 유효기간 문제)

## s0300200040p1 · 계약서 미리보기

**출처**: `ErpContractForm.dc.html` 의 계약서 모달 — 이미 구현되어 있음

- 1000×92vh, 2종 전환 탭: 이용계약서(4섹션) / 전대차계약서(10조)
- 인쇄 전용 CSS 포함. `@media print` 규칙을 누락하지 말 것
- 푸터: [닫기] / [인쇄] — 인쇄는 `window.print()`

**하드코딩 해소**

템플릿에 담당자명 "이정희", 센터명 "강남 삼성점"이 박혀 있다. 아래 순서로 조회한다.

```
1. 계약이 속한 지점의 담당자   (s0300000070 지점 설정)
2. 없으면 조직 기본 담당자      (s0300000070 조직 정보 · 계약서 기본값)
```

- 갑 = 에스원테크(조직 정보), 을 = 회원(계약 입주사)
- 계약서 문안은 `docs/` 에 별도 텍스트로 분리하고 치환 변수로 채운다.
  JSX에 문안을 직접 쓰지 말 것 — 법무 검토 시 수정 지점이 흩어진다

## s0300200040p2 · 상태 전이 확인

**출처**: `components/ds/Dialog.tsx` + `ErpContractForm.dc.html` 의 확인 모달

하나의 컴포넌트로 3종을 처리한다. 액션별로 문구·입력 항목·버튼 색만 달라진다.

| 액션 | 전이 | 추가 입력 | 주 버튼 |
|---|---|---|---|
| 계약확정 | `create`/`draft` → `confirmed` | 없음 | primary |
| 계약취소 | `draft` → `cancelled` | 취소 사유 (필수) | danger |
| 계약종료 | `confirmed` → `terminated` | 종료일(DatePicker) + 사유(필수) | danger |

**경고 문구 — 반드시 표시**

- 계약확정: "확정 후에는 계약 정보(섹션 2)를 수정할 수 없습니다.
  조건 변경이 필요하면 종료 후 재계약해야 합니다."
- 계약종료: "종료 후에는 되돌릴 수 없습니다."

**전이 규칙**

- `confirmed` 이후 섹션 2 잠금. 섹션 1·3은 계속 수정 가능
- `cancelled` / `terminated` 는 종료 상태. 이후 전이 없음
- 버튼 노출은 현재 상태에 따라 분기. 불가능한 전이는 버튼을 렌더링하지 않는다
  (비활성으로 두지 말 것 — 없는 동작이 보이면 문의가 발생한다)

## s0300000010p1 · 조직 선택

**출처**: `ErpAuth.dc.html` 의 로그인 폼 영역

2단계 로그인의 두 번째 단계. 삐용의 조직 선택 임시 토큰 방식을 그대로 사용한다.

- 좌 44% 폼 + 우 56% 브랜드 패널 구조 유지. **폼 영역만 교체**한다
- 폼 내용: "소속 조직을 선택하세요" + 조직 카드 리스트
  - 카드 높이 72px, 조직명 16px + 역할 배지(운영사/입주사) 13px
  - 선택 시 인디고 테두리 2px
- 소속 조직이 1개면 이 화면을 건너뛰고 바로 홈으로
- 하단: [로그인] primary + [다른 계정으로] ghost

**로그인 후 홈 분기**

```
운영사 → /dashboard
입주사 → /booking
```

입주사 대시보드는 존재하지 않는다. 사이드바에도 렌더링하지 않는다.
