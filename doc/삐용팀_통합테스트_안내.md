## 환경 파일

- 견본: 저장소 `env.example/` 의 네 파일 `common.env` · `erp-api.env` · `erp-web.env` · `admin.env` 이다. 칸 이름만 있고 값은 없다.
- 새 폴더 위치: 환경 변수 **`SWONBIZ_ENV_DIR`** 로 정한다. 없으면 `C:\workspace\env\` 이다.
- 읽는 쪽:
  - API 는 `common` + `erp-api` 를 읽는다.
  - 스크립트는 `common` + `admin` 을 읽는다.
  - 관리자 DB 계정은 `admin.env` 에만 둔다.
- ★ **실제 값은 git 에 없다.** 각자 PC 에서 견본을 보고 만든다. 새 폴더의 파일은 저장소에 넣지 않는다.
- 나누기 스크립트 `scripts/oneoff/2026-10-24-env-split.mjs` 는 옛 `.env` 세 개(루트 · `packages/api` · `packages/web`)를 새 폴더의 네 파일로 나눠 담는다.

  ```
  node scripts/oneoff/2026-10-24-env-split.mjs            (보기 — 칸 이름과 갈 파일만 보인다)
  node scripts/oneoff/2026-10-24-env-split.mjs --apply    (쓰기)
  ```

  - 값은 화면에 내지 않는다.
  - 옛 `.env` 는 읽기만 하고 고치거나 지우지 않는다.
  - 다음 경우에는 아무것도 쓰지 않고 멈춘다:
    - 새 폴더에 파일이 이미 있음
    - 표에 없는 칸이 있음
    - 읽는 방법에 따라 값이 달라지는 칸이 있음
- **아직 옛 `.env` 로도 뜬다(옛 경로 장치).**
  - 새 폴더 자체가 없으면 API 는 옛 `packages/api/.env` 를 읽는다.
  - 폴더는 있는데 파일이 빠졌으면 옛 경로로 돌아가지 않고 멈춘다.

## 통합 시험 — `verify_partner_sync_real` 로 확인할 항목

받기 세 개는 다음과 같다.

| # | 받기 | 주소 |
|---|---|---|
| 1 | 법무 회사 정보 | `POST <ERP API 주소>/legal/bbiyong/org-changed` |
| 2 | 입주사 회사 정보 | `POST <ERP API 주소>/companies/bbiyong/org-changed` |
| 3 | 입주사 직원 정보 | `POST <ERP API 주소>/companies/bbiyong/member-changed` |

받기 세 개 각각에 대해 확인한다.

| 확인 | 부르는 토큰 | 기대 |
|---|---|---|
| 운영사 | 운영사 계정(`S021100010` 있음) | 받음(200) |
| 자기 회사 | 대상 회사(직원이면 그 직원이 속한 회사)의 회원 계정 · 수정 키 있음(회사 받기 `ORG_SELF` · 직원 받기 `MEMBER_SELF`) | 받음(200) |
| 자기 회사 · 키 없음 | 같은 경우인데 수정 키 없음(C3) | **403** |
| 남의 회사 | 다른 회사의 회원 계정 | **403** `운영사이거나 그 회사의 토큰이 아닙니다` |

직원 받기에서 **그 직원이 ERP 에 없을 때**를 더 확인한다(통합 시험 C1).

| 확인 | 부르는 토큰 · 본문 | 기대 |
|---|---|---|
| 키 있음 | 비입주사 대표 토큰 · ERP 에 없는 직원 · 자기 회사 `orgId` · 직원 수정 키 있음 | 200 `{ "ok": true, "applied": false, "skipped": "not_found" }` |
| 키 없음 | 같은 경우인데 직원 수정 키 없음 | **403** |
| 남의 회사 | 같은 경우인데 본문 `orgId` 가 다른 회사 | **403** |
| 단체 수정 키만(C4) | 같은 경우인데 직원 수정 키 없이 단체 수정 키(`ORG_SELF`)만 있음 | 200 `not_found` |

직원 받기에서 **대표 직원**을 더 확인한다(통합 시험 C4). 모두 자기 회사 토큰이다.

| 확인 | 대상 직원 · 토큰의 키 | 기대 |
|---|---|---|
| 대표 · `ORG_SELF` 만 | 그 회사의 활성 대표 · 단체 수정 키만 | 받음(200) |
| 대표 · `MEMBER_SELF` 만 | 그 회사의 활성 대표 · 직원 수정 키만 | 받음(200) |
| 대표 · 키 없음 | 그 회사의 활성 대표 · 수정 키 둘 다 없음 | **403** |
| 대표 아님 · `ORG_SELF` 만 | 대표가 아닌 직원 · 단체 수정 키만 | **403** |
| 대표 아님 · `MEMBER_SELF` | 대표가 아닌 직원 · 직원 수정 키 있음 | 받음(200) |

- 본문 · 응답 칸은 연동규격 문서 세 개를 본다: `doc/연동규격_{법무_회사정보,입주사_회사정보,입주사_직원정보}_받기.md`.
- 법무 회사 정보 수정 열기(F002)는 받기가 아니라 ERP 화면 · 저장 쪽 규칙이다. 이 대본의 확인 항목이 아니다.
