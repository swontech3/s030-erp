### 검색

목록 위 카드 한 장. flex-wrap, gap 12, 패딩 16 — 문의일자 `flex: 2 1 300px`, Select 두 개 `flex: 1 1 160px`. 넓으면 한 줄, 좁으면 문의일자가 한 줄을 차지하고 Select 둘이 다음 줄. 라벨 12px `--text-muted`, 입력 44px.

| 항목 | 입력 | 값 |
|---|---|---|
| 문의일자 | `type=date` 2개 **from ~ to** | 양 끝 날짜 포함. 한쪽만 넣으면 그 날 이후 / 그 날 이전. 둘 다 비우면 전체. from 의 `max` = to, to 의 `min` = from 으로 뒤집힌 범위를 막음 |
| 상태 | Select | 전체 · 접수 · 답변완료 (판정은 `03-thread.md#2`) |
| 문의유형 | Select | 전체 · 입주문의 · 법무설립문의 · 세무문의 · 연구소설립문의 · 기타 |

- **바꾸면 즉시 적용**하고 1페이지로. 검색 버튼 없음
- 하나라도 걸리면 「전체 23건」 → 「검색 결과 4건」
- **[검색조건 초기화]** — 「문의유형」 라벨과 같은 줄 **오른쪽 끝**에 항상 표시. 텍스트 버튼 12px/700 `--color-primary`(hover `--color-primary-hover`) + `rotate-ccw` 12px, 줄 높이 20px (라벨과 같음) — 검색 카드 높이를 늘리지 않습니다. 조건이 없을 때 눌러도 아무 일 없음
  - 라벨 안(`<label>`)에 넣지 마세요. 누르면 Select 에 포커스가 갑니다 — 라벨과 버튼을 형제로 두고 `for` 로 연결
- 0건: `search-x` 48px + 「조건에 맞는 문의가 없습니다」 + [검색조건 초기화]
- 글 보기에서 목록으로 돌아와도 조건 유지 (URL 쿼리 `?from=&to=&status=&type=&page=` 권장)
- 글이 하나도 없으면 검색 카드를 숨깁니다

## 3. 문의하기 — s0300500070p1

섹션 카드 4개 (radius-lg, 패딩 24/20). 섹션 제목 22px/600 + 3×16px `--color-primary` 바.
**필수 항목은 라벨 앞 5px 원 `--color-danger`** (동의 체크박스의 「(필수)」도 `--color-danger`), 선택 항목은 라벨 뒤 「(선택)」.

모달이 아니라 **별도 페이지**입니다 (`/inquiry/new`). 입력 항목이 길고 모바일에서 키보드가 올라오면 모달 스크롤이 불편하기 때문입니다.

| 섹션 | 필드 | 필수 | 검증 · 입력 |
|---|---|---|---|
| 연락처 | 이름 | ● | 공백 제외 1자 이상 |
| | 연락처 | ● | 숫자 10자리 이상. 입력 중 `010-0000-0000` 마스크 (`tenant-contract/05-logic.md#5` 와 같음) |
| | 이메일 | ● | `^[^\s@]+@[^\s@]+\.[^\s@]+$` |
| | 회사명 | | |
| 문의 내용 | 문의 유형 | ● | 버튼 5개 — 입주문의 · 법무설립문의 · 세무문의 · 연구소설립문의 · 기타. `repeat(auto-fill, minmax(128px, 1fr))` — 800px 에서 한 줄, 390px 에서 2열 |
| | 문의 내용 | ● | 1000자, 우측 하단 「0 / 1000」 |
| 비밀번호 | 비밀번호 | ● | 4자 이상. 안내 「내 글과 답변을 확인하고 추가 질문을 남길 때 필요합니다」 |
| 동의 | 개인정보 수집·이용 | ● | 체크박스 20px. 수집 항목 「이름, 연락처, 이메일, 회사명, 문의 내용」. 보유 기간 「등록일로부터 6개월 보관 후 파기」. 박스 안에 「이름 일부와 문의 유형이 목록에 표시됩니다 (예: 김** · 입주문의)」 |

두 열 그리드는 `repeat(auto-fit, minmax(240px, 1fr))` — 좁아지면 자동으로 한 열.
입력 글자는 모두 16px (iOS 자동 확대 방지).

### 오류 표시 — ★ 지난 검토에서 확정

```
처음        오류 표시 없음
[문의 등록]  미입력 항목 전부 빨간 테두리 --color-danger + 필드 아래 12px 문구
            상단 배너 「입력하지 않은 필수 항목이 3곳 있습니다」 + 맨 위로 스크롤
그 뒤 입력   고친 항목은 즉시 회색 테두리로. 배너 개수도 즉시 갱신
포커스       오류 상태여도 포커스 링(3px --focus-ring)은 항상 보임
```

- 테두리 규칙은 `[data-err="1"] { border-color: var(--color-danger) !important }` 하나로 처리했습니다. 포커스 링은 `box-shadow` 라 겹치지 않습니다
- 문의 유형 세그먼트와 동의 카드도 같은 규칙으로 테두리만 빨갛게
- 비밀번호 오류가 보일 때는 안내 문구를 숨깁니다 (한 줄만)

### 등록 제한 (스팸) — 서버 응답

필수 항목이 다 채워진 뒤 서버가 막는 경우입니다. 같은 자리(상단 배너)에 띄우고 맨 위로 스크롤, **입력값은 지우지 않습니다.**

| 조건 | 아이콘 | 제목 (14px/700 `--color-danger`) | 설명 (14px `--text-body`) |
|---|---|---|---|
| 같은 연락처 오늘 3건 | circle-alert | 오늘은 더 등록할 수 없습니다 | 같은 연락처로 하루 3건까지 남기실 수 있습니다. 이미 남기신 글에 추가 질문으로 이어 쓰시거나 070-4355-2312 로 연락 주세요. |
| 같은 연락처 등록 후 1분 이내 | clock | 잠시 후 다시 등록해 주세요 | 방금 문의를 등록하셨습니다. 1분 뒤에 다시 등록할 수 있습니다. 입력하신 내용은 그대로 남아 있습니다. |

배너 모양은 필수 항목 배너와 같고(`--color-danger-bg`, radius-lg), 두 줄입니다. 다시 [문의 등록]을 누르면 배너를 지우고 다시 요청합니다.
시안에서는 확인 컨트롤 바 `submitResult` 로 재현합니다. 판정 기준은 `04-data-model.md#4`.
