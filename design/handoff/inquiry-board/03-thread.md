# 답변 · 추가 질문 스레드

글 보기의 「답변」 아래는 **하나의 시간순 목록**입니다. 원글 뒤에 운영자 글과 고객 추가 질문이 번갈아 쌓입니다.

```
원글 (고객)                              ← 정보 카드. 스레드에 포함하지 않음
 ├ 운영자 답변   2026.09.25 10:12 · 2026.09.26 수정됨
 ├ 추가 질문     2026.09.26 09:40          ← 글 하나에 1회
 ├ 전화 답변     2026.09.26 11:05 · 담당 이정희
 └ (대기 카드)   마지막이 고객 글일 때만
```

---

## 1. 메시지 3종

| kind | 누가 | 카드 | 머리 | 본문 |
|---|---|---|---|---|
| `text` | 운영자 | `--surface` + border | 로고 32px 원(`--color-accent-bg`) · 「SwonBiz {담당자}」 14px/700 · 시각 12px | 15px/1.75 pre-line |
| `phone` | 운영자 | `--surface` + border | 전화 아이콘 40px 원 · 「전화로 답변드렸습니다」 16px/700 · 「{시각} · 담당 {담당자}」 13px | **없음** |
| `customer` | 고객 | **`--surface-alt`** + border | 사람 아이콘 32px 원(흰 배경 + border) · 「추가 질문」 14px/700 · 시각 12px | 15px/1.75 pre-line |

고객 글과 운영자 글은 **배경색으로만** 구분합니다. 좌우 정렬(채팅형)은 쓰지 않았습니다 — 긴 답변이 좁아져 읽기 어렵습니다.

카드 간격 12px. 시각은 `YYYY.MM.DD HH:mm`, tabular-nums.

### 대기 카드

마지막 글이 고객 글이거나 스레드가 비었으면 맨 아래에 붙입니다.

```
점선 테두리 · --surface-alt · 시계 아이콘 40px
「답변을 준비하고 있습니다」 16px/700
「영업일 1일 내 담당자가 이곳에 답변하거나 전화드립니다.
  별도 알림은 보내지 않으니 이 글에서 확인해 주세요.」 14px
```

## 2. 상태 — 마지막 글로 판정

| 마지막 글 | 목록·제목 옆 뱃지 |
|---|---|
| 없음 (원글만) | 접수 |
| 고객 추가 질문 | **접수** |
| 운영자 `text` · `phone` | 답변완료 |

```js
const status = (!thread.length || thread.at(-1).kind === "customer") ? "접수" : "답변완료";
```

추가 질문을 남기면 **다시 접수로 돌아갑니다.** 운영자 목록에서 「답변 필요」 글을 찾는 기준이 그대로 이 값입니다.
저장 컬럼으로 두든 조회 시 계산하든, 화면은 이 규칙과 같아야 합니다.

## 3. 운영자 답변 수정 — 「수정됨」

- **수정만 됩니다. 삭제는 없습니다.** (운영자·고객 모두 개별 글 삭제 불가. 예외는 5번의 보관 기간 삭제)
- 수정 대상: `text` 의 본문. `phone` 은 본문이 없으므로 수정할 것이 없습니다 (기록 시각·담당자는 그대로)
- 수정하면 시각 옆에 **「· 2026.10.02 수정됨」** — 마지막 수정일만, 날짜만(시각 없음)
- 수정해도 **원래 등록 시각과 스레드 순서는 그대로**입니다. 맨 아래로 옮기지 않습니다
- 수정 이력(이전 본문)은 고객 화면에 보여주지 않습니다. 보관 여부는 서버 판단

```html
<div class="when"><span>2026.09.25 10:12</span><span>· 2026.10.02 수정됨</span></div>
```
좁은 폭에서는 두 번째 span 이 다음 줄로 내려갑니다 (flex-wrap).

> 같은 날 수정해도 「수정됨」을 붙입니다. 고객이 이미 읽은 내용이 바뀌었을 수 있기 때문입니다.

## 4. 고객 추가 질문

| 항목 | 규칙 |
|---|---|
| 횟수 | **글 하나에 1회.** 한 번 등록하면 입력란을 없애고 안내로 바꿉니다 (아래) |
| 누가 | 그 글의 **비밀번호를 통과한 사람만.** 입력란은 글 보기 화면에만 있습니다 |
| 언제 | 상태와 상관없이 항상 (답변 전에도 덧붙일 수 있음) |
| 길이 | 1~1000자. 공백만이면 「내용을 입력해 주세요」 + 빨간 테두리, 입력하면 해제 |
| 등록 후 | 스레드 맨 아래에 추가 · 입력란 비움 · 상태 → 접수. 페이지 이동 없음 |
| 수정·삭제 | 불가. 입력란 아래 「추가 질문은 한 번만 남길 수 있고, 등록 후 수정·삭제할 수 없습니다.」 |

### 1회 사용 후

입력란 자리에 안내 카드 (`info` 16px, 14px `--text-body`):
```
추가 질문은 한 번만 남길 수 있습니다. 더 궁금한 점은 070-4355-2312 로 연락 주시거나 새 문의를 남겨 주세요.
```
판정은 스레드에 `customer` 메시지가 있는지 하나로 합니다. 서버도 두 번째 등록을 **409** 로 거절하세요.

### 비밀번호 세션

비밀번호 확인 후 추가 질문 등록 요청에도 **같은 권한이 필요합니다.** 글 보기 응답과 함께 짧은 수명의 열람 토큰을 내려 주고,
추가 질문 POST 에 그 토큰을 요구하세요. 토큰 없이 `/inquiry/{id}/messages` 에 쓸 수 있으면 누구나 남의 글에 글을 붙일 수 있습니다.

토큰 만료 후 등록하면 → 비밀번호 화면으로 보내고, **입력하던 내용은 버리지 말고** 확인 후 입력란에 되살려 주세요.

## 5. 운영자 문의 관리(s0300200080)가 해야 할 일

개발에서 기존 목록 모양으로 만드는 화면입니다. 고객 화면과 맞아야 하는 부분만 적습니다.

| 기능 | 고객 화면에 보이는 결과 |
|---|---|
| 글 답변 등록 | `text` 메시지 · 「SwonBiz {운영자 이름}」 · 상태 답변완료 |
| 전화 답변 기록 | `phone` 메시지 · 「전화로 답변드렸습니다 · 담당 {이름}」 · 상태 답변완료 |
| 답변 수정 | 같은 메시지 본문 교체 · 「{날짜} 수정됨」 |
| 목록 필터 | 「접수」 = 마지막이 고객 글 (2번 규칙) — 추가 질문이 달린 글도 여기에 다시 나와야 합니다 |
| 「보관 기간 지남」 표시 | 원글 등록일 + 6개월이 지난 글. **운영자 화면에만** — 고객 목록·글 보기에는 없음 |
| 문의 삭제 | 운영자가 확인 후 **글 전체(원글+스레드)** 를 삭제. 고객 목록에서 사라지고 비밀번호로도 열 수 없음 |

**답변(메시지) 단위 삭제 버튼은 두지 마세요.** 삭제는 보관 기간 처리를 위한 글 전체 삭제 하나뿐입니다.
기간이 지나지 않은 글을 지울 수 있게 할지는 운영 판단입니다 (스팸 제거용 등).
