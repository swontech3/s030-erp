# 예약 상태 · 권한 · 제한 규칙

## 1. 상태 3종

| 값 | 라벨 | 의미 | 그리드 | 뱃지 |
|---|---|---|---|---|
| `confirmed` | 확정 | 등록 즉시 이 상태 | 인디고 블록 | `--color-accent-bg` / `--color-primary-hover` |
| `cancelled` | 취소 | 사용자가 취소 | **표시 안 함** (시간 비움) | `--surface-alt` / `--text-caption` |
| `completed` | 종료 | 종료 시각이 지남 | 회색 블록 | `--surface-alt` / `--text-muted` |

`requested`(승인 대기) · `rejected`(반려)는 외부 예약(2차)에서 추가합니다. **이번에는 enum 에도 넣지 않는 것을 권장**합니다 —
넣어 두면 어느 화면이 그 값을 받았을 때 표시 규칙이 없습니다.

### 전이

```
(등록) ──→ confirmed ──취소──→ cancelled
                     └─종료 시각 경과──→ completed
```

되돌리는 전이는 없습니다. 취소한 예약을 살리려면 새로 등록합니다.

### 종료 판정

`completed` 로 바꾸는 시점(배치·조회 시 갱신)은 서버 설계에 맡깁니다. 화면은 **저장값과 상관없이** 아래로 판정합니다 —
배치가 늦어도 지난 예약이 확정으로 보이지 않게 하기 위해서입니다.

```js
function statusOf(b) {
  if (b.status === "cancelled") return "cancelled";
  if (b.status === "completed" || endAt(b) <= now) return "completed";
  return "confirmed";
}
```

진행 중(시작 ≤ 현재 < 종료)은 별도 상태가 아니라 `confirmed` 입니다. 현황판만 「사용 중」으로 표현합니다.

## 2. 보기 권한 — 마스킹

템플릿 규칙 그대로입니다.

| 보는 사람 | 우리 조직 예약 | 타사 예약 | 운영사 예약 |
|---|---|---|---|
| 운영자 | 전부 | 전부 | 전부 + 「운영사」 뱃지 |
| 입주사 | 전부 | 시간 + **「예약됨」** | 시간 + 「예약됨」 |

- 「예약됨」 블록은 클릭해도 열리지 않습니다
- **마스킹은 서버에서.** 입주사 응답에 타사 예약의 `title` · `orgId` · `people` · `memo` · 예약자 정보를 담지 마세요.
  화면에서 가리는 것만으로는 개발자 도구로 보입니다
- 월간 툴팁의 조직명은 운영자 전용 응답에만

## 3. 예약 제한

| 규칙 | 입주사 | 운영자 | 판정 기준 |
|---|---|---|---|
| 회의실 운영시간 안 | ● | ● | `open ≤ start`, `end ≤ close` — Select 가 애초에 밖을 만들지 않음 |
| 30분 단위 | ● | ● | 모든 시각이 30분 배수 |
| 회의실 최소 이용시간 | ● | ● | `end − start ≥ room.minMinutes` |
| 회의실 최대 이용시간 | ● | ● | `end − start ≤ room.maxMinutes` (1회 기준) |
| 같은 회의실 시간 중복 | ● | ● | 취소 제외, 자기 자신 제외 |
| 지난 시각 | ● | — | `start < now` 면 불가 (진행 중인 30분 칸도 불가) |
| 4주 앞까지 | ● | — | `date ≤ 오늘 + 27일` (오늘 포함 28일) |
| 하루 2시간 | ● | — | **조직 기준, 그 날 모든 회의실 합산, 취소 제외** + 이번 예약 ≤ 120분 |

> ★ 운영자에게도 최소·최대 이용시간을 적용했습니다. 「셋 다 제한 없음」을 입주사 3개 규칙으로 해석했습니다.
> 운영자도 회의실 최소·최대를 넘겨야 하면 알려 주세요 — `checkTime` 의 두 줄에 `isTenant()` 조건만 붙이면 됩니다.

> ★ 하루 2시간은 **조직 단위 · 회의실 합산**으로 정했습니다 (템플릿의 「조직당 일 2시간」 기준).
> 사람 단위 또는 회의실별이면 `usedMinutes` 의 필터만 바뀝니다.

### 운영자가 입주사 대신 등록할 때

제한은 **등록하는 사람** 기준입니다. 운영자가 브릿지랩 이름으로 3시간을 잡아도 막지 않습니다.
다만 그 3시간은 브릿지랩의 그 날 사용량에 **포함**되어, 브릿지랩 직원이 같은 날 더 예약하려 하면 막힙니다.

### 수정 시

등록과 같은 검사를 다시 합니다. 단 충돌과 하루 2시간 계산에서 **수정 중인 예약 자신은 뺍니다** —
1시간 예약을 1시간 30분으로 늘릴 때 「이미 1시간 사용」으로 막히면 안 됩니다.

## 4. 수정 · 취소 권한

| | 확정 · 시작 전 | 확정 · 진행 중 | 확정 · 지난 시각 (배치 전) | 종료 | 취소 |
|---|---|---|---|---|---|
| 운영자 | 수정·취소 | 수정·취소 | 상세 (종료로 판정) | 상세 | — |
| 입주사 · 우리 조직 | 수정·취소 | 상세 | 상세 | 상세 | — |
| 입주사 · 타사 | — | — | — | — | — |

「—」 는 열리지 않음. 취소 예약은 그리드에 없으므로 여는 경로가 없습니다.

## 5. 그리드 칸 차단 (입주사)

| 조건 | 칸 표시 | 드래그 |
|---|---|---|
| 칸 시작 < 현재 | `--surface-alt` + not-allowed | 시작 불가, 지나갈 수도 없음 |
| 날짜 > 오늘+27일 | 사선 줄무늬 + not-allowed | 시작 불가 |
| 하루 2시간 초과 | **칸은 막지 않음** | 모달에서 오류로 안내 |

하루 2시간을 칸에서 막지 않는 이유 — 어떤 칸이 막힐지는 선택 길이에 따라 달라지므로 칸 단위로 표현할 수 없습니다.
