### 게이트 — `004_rename_tenant.sql` 적용

페이즈가 아니라 **일정 조율이 필요한 단발성 작업**이라 번호를 매기지 않는다. 페이즈 1과 2 사이에 반드시 끼운다 — 페이즈 2(기준관리)의 첫 작업이 `tb_s080_buildings`를 만지는데, 그 테이블의 `operator_id`(개명 전 `tenant_id`)가 이 게이트의 대상이다.

**절차** (`SPEC.md`·`BACKEND_ANALYSIS.md` §5 순서 6번 그대로):
1. 기존 S-WonERP 앱 정지
2. `pg_dump` 백업
3. `supabase/migrations_hold/004_rename_tenant.sql` 적용 (적용 직전에만 이 폴더에서 꺼낸다)
4. S-WonERP `schema.prisma`의 `@map("tenant_id")` → `@map("operator_id")` 전량 수정
5. 앱 재기동 → 계약 목록·상세·등록, 청구 목록, 예약 등록 스모크 테스트

**이 게이트가 페이즈 1 안에 있지 않은 이유**: 페이즈 1의 신규 코드(Fastify·Mock 인증)는 `tenant_id`/`operator_id`를 전혀 참조하지 않는다. 반면 이 게이트는 **신규 코드와 무관하게 기존 앱만 건드리는 별도 배포 창**이다. 페이즈 1이 끝나기 전에 실행해도 무방하지만, 실행 시점과 페이즈 1의 완료 시점을 억지로 묶을 이유가 없어 별도로 뺐다. **다만 페이즈 2 착수 전에는 반드시 끝나 있어야 한다.**

| ⑩ | 겸직 지원 여부 | `s0300000010p1`(조직 선택) 존폐 | 페이즈 1에서 이 화면을 아예 만들지 않고 보류 — 회신 오면 추가 페이즈 없이 페이즈 1 재개장(reopen) |
| ⑬ | 삐용 조직 목록 조회 API | `link_s020_org_id` 연결 UI의 드롭다운 | 페이즈 3에서 수기 입력으로 시작 — UX 개선일 뿐 기능 자체는 막히지 않음 |
| ⑧ | BILLING의 `provider_only_yn` | 청구 화면(3차) 대상 분류 | 3차 문제. 1차 로드맵에 영향 없음 |
| ⑨ | `050` 공개 화면 마스터 등록 여부 | `ACL-09` 제출 범위 | 페이즈 5 완료 후 제출 시점 |
| 6 | 한 입주사 동시 복수 계약 허용 여부 | 계약 폼 카디널리티 | **페이즈 4 착수 전 결정 필요** — 스키마상 이미 허용(`company_id` UNIQUE 없음)이라 막을 이유가 없으면 기본값(허용)으로 진행 |

**우선순위**: ⑫·⑦이 최상위(2단계 진입 자체를 막음)지만, **1차 로드맵의 6개 페이즈 중 어느 것도 이 둘을 기다리지 않는다.** 회신이 늦어져도 1차는 Mock 상태로 완주하고, 회신이 오면 어댑터 구현체 하나(`HttpBbiyongAcl`/`HttpBbiyongAuth`)만 교체한다.

## 5. 페이즈별 예상 소요 시간

**전제**: 풀타임 풀스택 개발자 1명 기준 인일(person-day). 팀 규모가 다르면 비례 조정. 리뷰·QA 시간 포함, 삐용 실연동(2단계)·청구(3차)는 제외.

| 페이즈 | 예상 | 근거 |
|---|---:|---|
| 1. 플랫폼 기반 + 로그인 | 6~8일 | 스캐폴딩 + DS 15종 이관이 가장 크다. 세션·ACL 어댑터는 인터페이스만이라 상대적으로 가볍다 |
| *(게이트)* 004 적용 | 0.5~1일 | SQL 자체는 즉시. 앱 정지 창 조율·스모크 테스트가 대부분 |
| 2. 기준관리 | 4~5일 | 4계층 CRUD + 삭제 방지. 로직은 단순하나 팝업 5종 |
| 3. 입주사 관리 | 3~4일 | CRUD 2종 + 마스터-디테일 + 조직 연결 UI(신규) |
| 4. 계약 | 10~13일 | 1차 최대 난이도. 섹션 4개·상태 5종·항목/사용자 한도·계약서 2종·이력·스냅샷·`005`/`006` 마이그레이션 추가 작성 포함 |
| 5. 회의실 예약 + 현황판 | 6~8일 | 동시성 검증·3단 반응형·마스킹·키오스크. `timestamptz` 전환이 걸리면 상단 근접 |
| 6. 대시보드 | 2~3일 | 화면은 디자인 완료 상태, 집계 쿼리 위주 |
| **합계** | **약 32~42일** (6.5~8.5주) | 삐용 회신 대기 없이 이 기간 내 1차 완주 가능 |

**가장 불확실한 항목**: 페이즈 4(계약)와 페이즈 5의 `timestamptz` 전환. 둘 다 범위가 넓거나(계약) 후속 마이그레이션이 걸려 있어(예약) 실제 소요가 상단으로 붙기 쉽다.
