## 1. ★ 단체코드 — ERP는 보내지 않겠습니다

### 요청

**ERP 경로로 들어오는 회사는 삐용이 단체코드를 만들어서 붙여 주십시오.**
`orgCode`를 ERP가 정해서 보내지 않겠습니다.

### 사유

단체코드는 **삐용 안에서 쓰는 식별자**입니다. ERP 입주사에게는 아무 의미가 없는 값이고,
ERP는 회사를 `org_id` 하나로만 붙잡습니다. 뜻 없는 3자리를 운영자가 정하게 하면
"이 코드가 뭘 뜻하느냐"는 질문이 계속 생기고, 답이 없습니다.

만들어진 코드를 응답으로 내려주시면 ERP가 함께 보관해 두겠습니다. 나중에 삐용 운영
화면에서 회사를 대조할 때 쓰겠습니다.

### ★ 다만 — 그러면 멱등성이 사라집니다. 함께 요청드립니다

지금 "같은 요청을 두 번 보내도 회사가 하나만 생긴다"를 보장하는 것이 **단체코드의
전역 유일 제약 하나뿐**입니다. ERP가 코드를 보내지 않으면 그 장치가 없어지고,
응답이 유실됐을 때 재시도가 새 회사를 또 만듭니다.

**그래서 요청서 ①-A의 (a)안 — 요청 식별자 — 이 다시 필요해집니다.**

> ERP가 만들어 붙인 **요청 식별자**를 받아 주십시오.
> 같은 식별자로 두 번 오면 새로 만들지 말고 첫 번째 `org_id`를 그대로 돌려주시면 됩니다.

둘 중 하나는 반드시 있어야 하므로 묶어서 요청드립니다.

```
(가) ERP가 단체코드를 정해 보낸다          ← 회신하신 안. 멱등 O, 의미 없는 값을 사람이 정함
(나) 삐용이 코드를 만들고 요청 식별자를 받는다 ← ★ 이쪽을 요청드립니다
```

**(나)가 어려우시면 (가)로 가겠습니다.** 어느 쪽인지만 알려 주십시오.
회신 전까지 ERP는 화면에서 단체코드 입력을 빼 둔 상태로 진행합니다.

### `deletedYn` — 되살리지 않겠습니다

지워진 단체가 코드를 점유하는 건에 대해, **ERP는 그 회사를 되살리지 않습니다.**

그 조직 안에 예전 구성원·역할·부서·기록이 무엇이 남아 있는지 ERP가 볼 수 없기 때문입니다.
되살리면 모르는 계정들이 새 입주사 조직에 딸려 들어옵니다.

(나)로 가면 이 상황 자체가 생기지 않습니다. **코드를 만드실 때 지워진 단체가 점유한
코드까지 피해서 만들어 주시면 됩니다.**

나갔던 입주사가 다시 들어오는 등 되살림이 필요한 경우는 ERP가 자동으로 처리하지 않고
삐용에 개별 요청드리겠습니다.

## 2. ① S03 공통 모듈 — `ERPCORE` 제안

### 코드명

**`ERPCORE`** 를 제안합니다. 기존 `CORE` · `MAIL` · `OFFICE` 처럼 업무 단위 이름이라
결이 맞습니다.

### 무엇을 담는가

어느 업무에도 속하지 않지만 **ERP를 쓰는 모든 회사에 필요한 화면**입니다.

```
s030000050  ERP 셸 (사이드바 · 상단 바)
s030000060  대시보드
s030000080  접근 권한 없음
```

회의실 예약만 쓰는 입주사도, 세무만 쓰는 입주사도 이 화면들이 필요합니다.
이걸 `OFFICE` 같은 업무 모듈에 넣으면, `BOOKING` 만 구독한 회사는 로그인해도 화면 틀이
없어 빈 화면이 됩니다.

### mandatory 여부 — **조건부 자동**을 제안합니다

```
OFFICE · BOOKING · LEGAL · TAX · BILLING 중 하나라도 켜면
  → ERPCORE 자동 부착

삐용만 쓰는 회사 (경비결재·메일)
  → ERPCORE 안 붙음
```

`CORE` 처럼 무조건 자동으로 하면 ERP를 전혀 안 쓰는 회사에도 쓰지 않는 권한이 쌓입니다.
조건부면 그럴 일이 없고, 운영자가 셸 모듈을 깜빡해서 "구독은 됐는데 화면이 안 뜬다"는
사고도 안 납니다.

> **참고** — 권한관리 재구축 쪽에서 **모듈에 속하지 않고 전 회사 공통으로 깔리는 화면**을
> 담는 자리가 이미 설계돼 있다면, 별도 모듈 대신 그 자리를 쓰는 편이 낫습니다.
> 그쪽이 맞다면 `ERPCORE` 신설은 취소하고 세 화면을 그리로 넣어 주십시오.

## 3. ② ERP 화면 목록

### 등록 규칙 두 가지

- **팝업(`p{n}`)은 별도로 등록하지 않습니다.** 팝업은 부모 화면의 권한을 그대로
  따릅니다. 팝업에 독자적인 권한을 주면 부모가 잠긴 데이터가 팝업으로 새어 나갑니다
- **050 공개 화면은 등록 대상이 아닙니다.** 로그인 전에 열리는 화면이라 권한 판정
  대상이 아닙니다 (랜딩, 외부 신청, 키오스크 현황판)

### 1차 — 지금 시드 요청드리는 분량

| 화면 ID | 화면명 | 모듈 | 대상 | 상태 |
|---|---|---|---|---|
| s030000010 | 로그인 | ERPCORE | 무인증 | 구현 완료 |
| s030000050 | ERP 셸 | ERPCORE | 공통 | 구현 완료 |
| s030000060 | 대시보드 | ERPCORE | 운영사 전용 | 자리 화면 |
| s030000080 | 접근 권한 없음 | ERPCORE | 공통 | 구현 완료 |
| s030200010 | 입주사 목록 | OFFICE | 운영사 전용 | 설계 완료 |
| s030200020 | 입주사 상세 | OFFICE | 운영사 전용 | 설계 완료 |
| s030200030 | 입주사·계약 마스터-디테일 | OFFICE | 운영사 전용 | 설계 완료 |
| s030200040 | 계약 폼 | OFFICE | 운영사 전용 | 설계 완료 |
| s030200070 | 월별 청구 관리 | BILLING | 운영사 전용 | 설계 완료 |
| s030600010 | 회의실 예약 현황 | BOOKING | 공통 | 자리 화면 |

- **로그인(s030000010)** 은 등록만 하고 판정은 돌지 않습니다.
  이전 회신 ⑨ 에서 합의된 대로입니다
- **"운영사 전용"** 은 에스원테크 조직에만 내려보내는 화면입니다.
  입주 계약·청구는 예외 없이 운영사 전용입니다 — 옆 호실의 임대 조건이 한 번 새면
  되돌릴 방법이 없습니다

### 2차 이후 — 참고용 (지금 시드하지 않으셔도 됩니다)

| 화면 ID | 화면명 | 모듈 |
|---|---|---|
| s030000070 | 설정 | ERPCORE |
| s030100010 | 센터 관리 (건물·층·호실·회의실) | OFFICE |
| s030100020 | 표양식 관리 | OFFICE |
| s030200050 | 멤버 관리 | OFFICE |
| s030200060 | 신청 대기 목록 | OFFICE |
| s030600020 | 외부 예약 승인 큐 | BOOKING |

`LEGAL`(법무) · `TAX`(세무)는 화면이 아직 미확정입니다. 확정되면 별도로 보내겠습니다.

### 켜는 순서 확인

회신하신 순서대로 진행하면 되는 것으로 이해했습니다.

```
1  위 1차 10화면 시드
2  ERPCORE 모듈 생성
3  ERPCORE · OFFICE · BOOKING · BILLING 권한 견본 생성
4  모듈 use_yn='Y'
5  ERP가 moduleCodes 로 보낼 수 있음
```

**1·3을 건너뛰고 4만 켜면 안 된다**는 점 확인했습니다. ERP도 그 전까지는 `moduleCodes`를
비워서 보내겠습니다.

## 4. ③ 사업자등록번호 — **추가하지 마십시오**

`org010` 에 컬럼을 추가하지 않으셔도 됩니다.

ERP는 세금계산서·청구를 위해 사업자정보를 자기 테이블(`tb_s080_*`)에 이미 보관해야
합니다. 삐용에도 두면 같은 값이 두 곳에 생기고, 달라졌을 때 어느 쪽이 맞는지 다투게
됩니다. 회사 식별은 `org_id` 하나로 충분합니다.

> **"모르는 필드는 조용히 버려진다"** 는 안내 감사합니다. ERP 쪽 입력 항목 정의에
> **삐용에 보내는 값 / ERP만 보관하는 값**을 구분해 표시해 두겠습니다.
> 표시가 없으면 언젠가 누가 필드를 추가해 놓고 저장됐다고 믿게 됩니다.

## 5. ④ User-Agent

```
SwonBizERP/1.0 (s030)
```

ERP **서버**에서 나가는 호출에만 붙습니다. 브라우저에서 삐용으로 직접 가는 요청은
없습니다 — ERP는 삐용 토큰을 브라우저에 내려보내지 않습니다.

## 6. 확인한 것 (조치 불요)

- **`org_tp='N'`** — 서버가 고정하고 ERP 입주사도 `N`. 보내지 않겠습니다.
  이전에 "에스원테크가 `S` 여야 하는데 `N` 으로 나온다"고 문의드린 건은 이것으로
  해소된 것으로 정리하겠습니다
- **`mailAgentYn`** — 보내지 않겠습니다
- **`member_tp='C'`** — 삐용이 정한다는 점 확인했습니다. ERP는 보내지 않습니다
- **업무 실패도 HTTP 200** · 본문 `status`/`result` 로 판정 · 메시지 필드는 `massage`
- **필수 필드 누락만 Spring 기본 형식** — `result` 필드 없으면 검증 실패로 처리하겠습니다
- **409는 재시도하지 않고 삐용에 알림**
- **400 중복은 실패가 아니라 성공 경로** — `data.orgId` 를 그대로 씁니다
- **`org-list`** 는 `orgName`·`memberName` 을 빈 문자열로라도 반드시 보내겠습니다
- **`update-member-info`** 결함 알려주셔서 감사합니다. `init-pwd` 와 함께 보안 문서에
  올려 두겠습니다. 둘 다 쓰지 않습니다
- **대표 계정** — `pwd` 없이 등록하고, 등록 완료 화면 안내는
  "계정 개통은 별도 안내 예정" 으로 잡겠습니다
- **가동계 미반영** — ERP도 개발계(8082)에서만 붙입니다
