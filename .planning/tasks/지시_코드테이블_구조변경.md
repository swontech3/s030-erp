# 코드 테이블 구조 변경 (A안) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `use_tp` 를 이름 있는 카테고리 테이블로 승격하고, 상호 표기위치를 `NAME_POSITION` 으로 분리해 `parent_line_id` 를 없앤다.

**Architecture:** 마이그레이션 2본(013 · 014)으로 스키마와 데이터를 옮기고, 조회 함수 `listCodes()` 가 `(category, use_tp)` 쌍을 받도록 바꿔 `DISTINCT ON` 을 걷어낸다. 웹 계층은 `CodeOption = {category, code, name}` 그대로라 **변경 없다**.

**Tech Stack:** PostgreSQL 17.6 · 손으로 쓴 SQL 마이그레이션(`supabase/migrations/`) · `scripts/apply-migration.js` · `scripts/verify-*.js` (이 저장소의 DB 검증 관용구) · Fastify + node-postgres

**Spec:** `doc/CODE_MASTER_ANALYSIS.md` (분석 · 결정 · 반대 논거)

## Global Constraints

- 마이그레이션은 **`postgres` 역할로만** 적용한다 — `node scripts/apply-migration.js .env <파일>`
- 파일 안에 `BEGIN;` / `COMMIT;` 를 직접 쓴다 (`apply-migration.js` 가 파일 전체를 한 번에 보낸다)
- 마이그레이션 파일은 **머리말 주석으로 「왜」를 남기고, 하단에 「검증」과 「되돌리기」** 를 적는다 (`012_member_sort_order.sql` 형식)
- 테이블 접두어는 `tb_s080_*`
- `code_id` · `line_id` 는 `text` 이고 **기본값이 없다** — INSERT 시 식별자를 직접 준다
- `updated_at` 은 기존 두 테이블에서 `NOT NULL` 이고 **기본값이 없다** — INSERT 시 값을 준다
- `npm run` 은 실패해도 종료코드 0 을 낸다. 검증은 `node scripts/...` 를 직접 부르고 **출력의 실패 건수를 읽는다**
- DB: `.env` (포트 **54322**, 개발계)
- 이 작업은 **삐용과 무관하다** — 2026-09-19 사용자 확인: 삐용은 이 두 테이블을 보지 않는다

```ts
export interface CodeSpec {
  category: string;
  /** 코드 카테고리(`tb_s080_code_categories.use_tp`). 공통은 `'000'`. */
  useTp: string;
}

/**
 * 코드 라인 — `(build_id, category, use_tp)` 로 묶인 파티션 단위로 읽는다.
 *
 * ★ `use_tp` 는 **한 카테고리 안의 독립 파티션**이다(`doc/CODE_MASTER_ANALYSIS.md` §B-1).
 *   `000` 이 공통이지만 `001` 이 `000` 을 물려받지 않는다 — 각 파티션이 완결된 목록이다.
 *   그래서 호출자가 **어느 파티션인지 말해야 한다.**
 *
 * ★ 예전에는 `DISTINCT ON (category, code)` 로 `use_tp` 를 버렸다. 그 결과
 *   `ROOM_TP` 의 `ET`(기타)가 계약 폼에 새어 나왔다 — `001` 에만 있어 경쟁자가 없었기
 *   때문이다(§E-1). 파티션을 지정하면 그 문제가 생기지 않는다.
 */
export async function listCodes(client: ScopedClient, specs: readonly CodeSpec[]): Promise<CodeRow[]> {
  const { rows } = await q<CodeRow>(
    client,
    `SELECT l.category, l.code, l.name, l.sort_order
       FROM public.tb_s080_codes_line l
       JOIN unnest($1::text[], $2::text[]) AS w(category, use_tp)
         ON w.category = l.category AND w.use_tp = l.use_tp
      WHERE l.is_active = true
      ORDER BY l.category, l.sort_order, l.code`,
    [specs.map((s) => s.category), specs.map((s) => s.useTp)],
  );
  return rows;
}
```
